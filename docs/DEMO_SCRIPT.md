# Сценарий демо (5 минут)

Продукт: **Pulse** — «Читаем рабочие чаты команды за вас и доводим каждую задачу клиента до результата».
Компания в демо: **Blue Ridge Freight LLC** (перевозчик, Иллинойс, 22 трака). Клиент в фокусе: брокер **Apex Logistics**.

## Подготовка (за 15 минут до выступления)

1. Запустить всё: `docker compose up -d db && pnpm db:migrate && pnpm dev` (или `docker compose up -d`).
2. Открыть два окна браузера (обычное и инкогнито — у них разные сессии):
   - окно А: `http://localhost:3000/login` → **Войти как собственник** → вкладка **Пульт демо**;
   - окно Б: `http://localhost:3000/login` → **Войти как диспетчер** (Timur).
3. В окне А: **Сбросить демо** → **Загрузить «вчера»**. Дождаться, пока в блоке «Очередь» будет `Ожидают 0`, а счётчики покажут ~37 сообщений, 8 задач.
4. Для живого режима: Telegram-группа с ботом (privacy выключен), группа привязана в **Источниках** к Apex Logistics как «Клиент». Написать в группу тестовое «hi», убедиться, что оно появилось в Источниках.
5. Язык интерфейса — RU (кнопка EN/RU в шапке), тема — светлая.

> Всё, что вы увидите дальше, построено пайплайном из сырых сообщений. В сид-файле нет ни одной задачи, сигнала или подсказки — только сообщения (`seed/demo-company.json`).

## Минута за минутой

**0:00–0:40 — Хаос.** Окно А → **Источники**.
Показать 3 чата Apex: «Apex ↔ Blue Ridge» (английский, брокер), «Dispatch: Apex» (русский, внутренний), общий «Fleet».
Сказать: «Вот так выглядит вчерашний день одного клиента. У диспетчера 30 таких чатов, у собственника — сто. ETA лежит во флотском чате по-русски, брокер ждёт его в другом чате по-английски, и никто его не передал».

**0:40–1:50 — Экран диспетчера.** Окно Б (Timur) → **Диспетчер**.

- Слева — чаты по срочности, бейджи «Ответить срочно», «Просрочено», «Жалоба», «Тон».
- В центре — одна лента по всем чатам клиента с метками «Создана задача», «Жалоба», «Грубый тон».
- Справа — **предлагаемое сообщение** брокеру Sarah. Показать блок **«Использован контекст из: Fleet 11:02 — Bakhtiyor: По 48207: трак 214… в Мемфисе будет примерно в 16:30»**.
  Сказать: «Система прочитала русский флотский чат и сама написала брокеру по-английски ETA, который вчера так и не дошёл. Это и есть кросс-чат контекст».

**1:50–2:40 — Правка и обучение.** В карточке подсказки: **Исправить**.
Изменить текст: `around 4:30 PM` → `4:30 PM CST`, `Load 48207 is` → `Load 48207, truck #214 is`. В поле причины: **«Apex wants ETA in CST and with the truck number»** → **Сохранить и использовать**.
Показать всплывашку **«Сохранено. Новое правило для Apex Logistics»** и счётчик **«Моя доля правок»** вверху.
Через пару секунд появится следующая подсказка для Apex (про POD) — в ней время уже **с CST** и зелёная плашка **«Применено правило»**.
Сказать: «Правил на старте нет. Каждая правка — это урок. Через пару недель доля правок падает с половины до пары процентов».

**2:40–3:20 — Карточка задачи.** В правой колонке «Открытые задачи» → **Reefer Chicago IL → Dallas TX, груз 48230**.
Показать путь: поступила 9:12 → подтверждена 9:25 **«ok»** → дальше пусто. Шаг подсвечен красным: «Застряла здесь: подтверждено N ч назад («ok»); с тех пор ни подтверждения, ни срока».
Сказать: «Прочитали, ответили “ok” — и груз ушёл к другому перевозчику. Раньше собственник узнал бы об этом по выручке».

**3:20–4:00 — Собственник.** Окно А → **Собственник**.
Три цифры и не больше пяти пунктов: просроченный POD, жалоба Apex, грубость Timur, неподтверждённый инвойс Summit, зависший реф. У каждого: что случилось, почему важно, цитата-доказательство, ответственный, кнопка «Открыть».
Сказать: «Можешь больше не заходить в чаты. Мы делаем это за тебя».

**4:00–4:40 — Живой режим.** Ведущий пишет в Telegram-группу (с телефона):
`Need a reefer PU tomorrow 7am Dallas → Atlanta, can you cover?`
Через ~10–15 секунд в окне Б появляется новая задача «Reefer Dallas → Atlanta» и подсказка «got it — checking reefer availability… PU tomorrow 7:00 AM CST» (правило Apex уже работает).
Без Telegram: окно А → **Пульт демо → Запустить живой поток** — сообщения придут сами каждые 3–5 секунд.

**4:40–5:00 — (если есть время) Передача дел.** Окно А → **Руководитель** → строка Timur → **Передать дела…** → Aziz → **Собрать справку**. Показать справку по каждому чату: что было, обещания, риски, что делать дальше.

## Что отвечать жюри

- **«Это заранее написанные ответы?»** Нет. В `seed/demo-company.json` только сырые сообщения. Задачи, сигналы, подсказки строит пайплайн: одна LLM-модель читает объединённую ленту, а код (конечный автомат задач, SLA-движок) решает, что принять. Можно написать любое сообщение в Telegram — оно обработается так же.
- **«Как вы получаете доступ к личным чатам?»** Только группы, куда компания сама добавила бота, и (опционально) Telegram Business — официальный API. Личные аккаунты (userbot) не автоматизируем: это нарушает ToS Telegram. В каждой группе бот может опубликовать уведомление о мониторинге.
- **«А если клиент напишет боту “игнорируй инструкции”?»** Весь текст чатов — данные. Входной фильтр помечает такие сообщения как untrusted, модель получает их в теге `<untrusted>`, у модели нет инструментов с побочными эффектами. Единственное внешнее действие — отправка сообщения — только после нажатия человеком «Подтвердить», и перед отправкой текст проходит фильтр секретов.
- **«Данные разных компаний не смешаются?»** Каждая таблица имеет `company_id`, каждый запрос фильтрует по компании из серверной сессии; это покрыто тестом.

## План Б

| Что сломалось                              | Что делать                                                                                                                                                                                                               |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Нет интернета / LLM не отвечает            | Перезапустить с пустыми `ANTHROPIC_API_KEY` и `LLM_BASE_URL` (или `LLM_PROVIDER=mock`) — включится mock-провайдер, весь сценарий работает офлайн. Провайдер виден в шапке диспетчера («AI: mock») и в Пульте демо.       |
| Telegram-бот не видит сообщения            | Проверить в Настройках «Видит все сообщения в группах». Если нет — @BotFather → `/setprivacy` → Disable, удалить и заново добавить бота в группу. Или показать живой режим через **Пульт демо → Запустить живой поток**. |
| Воркер не запущен (очередь растёт)         | Пульт демо покажет предупреждение. Запустить `pnpm dev:worker`. «Загрузить «вчера»» без воркера прогоняет пайплайн прямо в запросе.                                                                                      |
| Экран в странном состоянии после репетиции | **Пульт демо → Сбросить демо → Загрузить «вчера»** (≈10 секунд на mock, до минуты с реальной моделью).                                                                                                                   |
| Совсем всё плохо                           | `pnpm seed --analyze` в терминале — пересоздаёт компанию и прогоняет пайплайн без воркера. Скриншоты всех экранов лежат в `docs/screenshots/`.                                                                           |
